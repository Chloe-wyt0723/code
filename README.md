# 一碰通血压记录小程序

一碰通是一款微信小程序，用于记录血压和脉搏。用户可以拍摄血压计屏幕或从相册选图，后端调用腾讯云 OCR 识别读数；识别结果需要用户核对后再保存。记录保存在当前设备的小程序本地存储中。

## 技术栈

| 部分 | 技术 | 用途 |
| --- | --- | --- |
| 小程序 | 微信小程序原生框架、JavaScript、WXML、WXSS | 页面展示、拍照选图、读数确认和本地记录管理 |
| 后端 API | Node.js 18+、Express | 接收图片、校验请求、调用图像预处理和 OCR |
| 图像处理 | Python 3、OpenCV、NumPy | 检测血压计屏幕、透视校正、增强对比度和二值化 |
| 文字识别 | 腾讯云 OCR SDK（GeneralAccurateOCR） | 识别图像中的文字和数字 |
| 部署 | Docker（可选） | 打包后端运行环境；服务对小程序提供 HTTPS 接口 |

## 工作流程

1. 用户在小程序拍照或从相册选取血压计照片。
2. 小程序压缩图片并转成 Base64，发送到后端 `POST /api/ocr`。
3. 后端运行 `preprocess_image.py`，尝试提取并校正屏幕区域，再增强图像。
4. 后端调用腾讯云 GeneralAccurateOCR；如果预处理图未识别到文字，会再尝试原图。
5. 小程序从识别文字中提取高压、低压和脉搏，供用户核对和修改。
6. 用户保存后，记录写入微信本地缓存。记录不会同步到服务器或其他设备。

## 环境要求

- 小程序：微信开发者工具，以及有权限使用的微信小程序 AppID。项目当前使用的 AppID 配置在 `project.config.json`。
- 后端：Windows、macOS 或 Linux 均可；需要 Node.js 18 或更高版本、Python 3、pip，以及 Python 包 OpenCV 和 NumPy。Docker 部署时由镜像安装 OpenCV。
- 腾讯云账号已开通文字识别服务，并准备好 OCR 调用密钥。
- 小程序调用的后端地址必须是 HTTPS，并在微信小程序后台配置为合法 request 域名。

## 测试账号

项目没有登录、注册或账号体系，因此没有测试账号或密码。首页显示的“用户 001”只是界面上的编码标识，不用于登录或身份验证。要在微信开发者工具中运行小程序，需要使用有权限的 AppID；调用 OCR 则需要在后端配置有效的腾讯云 OCR 密钥。

## 配置和运行后端

### 1. 设置腾讯云密钥

复制 `backend/.env.example` 为 `backend/.env`，在本地 `.env` 中填写腾讯云密钥。密钥只放在服务端，切勿写入小程序代码或提交到仓库。示例文件里的值仅为占位符：

```text
TENCENTCLOUD_SECRET_ID=你的SecretId
TENCENTCLOUD_SECRET_KEY=你的SecretKey
TENCENTCLOUD_REGION=ap-guangzhou
PORT=3000
```

`TENCENTCLOUD_REGION` 和 `PORT` 是可选项；不设置时分别使用 `ap-guangzhou` 和 `3000`。`PYTHON_BIN` 也是可选项，用于指定运行 OpenCV 预处理的 Python 可执行文件。`dotenv` 会自动读取 `backend/.env`；不要将含密钥的 `.env` 文件提交到版本库。

### 2. 安装并启动

在项目根目录执行：

```bash
cd backend
npm install
python -m pip install -r requirements.txt
npm start
```

Windows 环境中如果 `python` 命令不可用，可将命令里的 `python` 换成 `py`。如果系统安装了多个 Python 版本，也可以通过 `PYTHON_BIN` 环境变量指定后端调用的 Python 可执行文件。

启动后访问 `http://localhost:3000/health`，正常时会返回类似：

```json
{"ok":true,"provider":"tencent-ocr"}
```

`/health` 只检查服务是否启动，不会验证腾讯云密钥或实际 OCR 调用是否成功。

### 3. Docker 部署（可选）

在项目根目录构建镜像：

```bash
docker build -t yipengtong-ocr ./backend
```

运行时通过环境变量传入密钥，并按部署平台要求映射端口、配置 HTTPS。容器默认监听 `3000` 端口。上线前应在实际服务器环境访问 `/health`，并用真实设备完成 OCR 调用验证。

## 配置并运行小程序

1. 在微信开发者工具中导入项目根目录，按项目配置选择对应 AppID。
2. 编辑根目录 `config.js`，把 `API_BASE_URL` 设置为后端的 HTTPS 根地址。例如：

   ```js
   const API_BASE_URL = 'https://bp.example.com';
   ```

   地址不要包含末尾的 `/api/ocr`；小程序会自动拼接该路径。仓库当前配置指向已有的云端地址，部署到其他地址时需要替换。

3. 在微信公众平台小程序后台，将该 HTTPS 域名添加到服务器域名的 `request` 合法域名列表。
4. 在开发者工具编译运行；真机使用前，确认域名已配置且后端可从公网访问。

开发者工具的本地调试设置可能允许跳过域名校验，但这不能替代真机和正式环境的合法域名配置。

## 小程序使用方法

1. 在首页点击“拍照记录血压”，对准血压计显示屏拍摄；也可以从相册选择已有照片，或直接手动输入。
2. 等待 OCR 识别。识别可能不完整或有误，请对照血压计屏幕，核对并修正高压、低压和脉搏。
3. 点击保存。数据通过输入范围校验后，会保存在本机；异常读数会显示提示。
4. 首页展示最近一次测量和历史记录。可删除单条记录；清除小程序本地数据会同时移除这些记录。

照片会发送到配置的 OCR 后端进行识别。当前后端在内存中处理图片，不将原图写入文件或数据库。血压记录只保存在本机小程序缓存中。

## 主要功能入口

- **首页及测量入口**：`pages/index/index.wxml` 中的拍照、相册和手动输入按钮，分别绑定 `takePhoto`、`chooseFromAlbum` 和 `openManualEntry`；对应交互逻辑在 `pages/index/index.js`。
- **OCR 识别**：小程序 `recognizePhoto()` 请求 `config.js` 中的服务地址，并调用后端 `POST /api/ocr`。服务端入口为 `backend/server.js`，图像预处理在 `backend/preprocess_image.py`。
- **核对与保存**：确认弹窗中的读数输入框绑定 `onValueInput`，保存按钮绑定 `saveRecord`；保存和删除操作使用微信本地存储，不会写入后端数据库。
- **历史记录**：首页由 `loadRecords()` 读取本地记录，显示最新一条及其余历史；删除按钮调用 `deleteRecord()`。
- **后端状态检查**：部署后访问 `/health`。该接口只报告服务进程状态，不验证 OCR 密钥或腾讯云调用是否可用。

## 用户信息与隐私处理

- 首页以“用户 001”这类编码标识显示用户，不展示真实姓名；如需区分多人，可使用不含姓名、手机号等个人信息的内部编号。
- 当前源码没有姓名、联系电话或手机号的录入、存储、上传和展示功能，也没有用户身份认证或联系方式收集流程。请勿将真实姓名、电话号码、身份证号等个人信息写入页面、记录或日志。
- OCR 请求只发送用于识别的血压计照片。拍摄前请检查照片中是否包含姓名、电话号码、地址、就诊卡或其他不相关个人信息；当前程序不会自动识别或遮挡这些信息。
- 照片会发往 `config.js` 配置的后端及腾讯云 OCR 服务。部署者应保护服务端密钥和访问日志，并按实际业务需要告知用户数据用途、处理方式和保留期限。
- 血压测量记录可能属于敏感健康信息。当前实现将其保存在使用设备的小程序本地缓存中；共享设备时应注意设备访问权限，卸载或清理小程序数据前应考虑记录会被删除。

## 接口说明

### `GET /health`

检查服务进程是否运行，成功返回服务状态。

### `POST /api/ocr`

请求体为 JSON：

```json
{"image":"<Base64 图片内容>"}
```

成功响应示例：

```json
{"text":"SYS 120\nDIA 80\nPUL 72","requestId":"..."}
```

图片 Base64 长度上限为 10 MB。接口会校验图片数据，并按来源 IP 限制请求频率；错误时返回相应 HTTP 状态码和错误信息。

## 已知限制与使用注意

- OCR 仅用于辅助录入，保存前请自行核对读数。
- 照片质量、反光、倾斜角度及屏幕样式都可能影响识别效果；识别失败时可重新拍摄或手动输入。
- 异常值提醒依据代码中的固定阈值生成；文案提到“将推送到子女端”，但目前没有实现实际推送功能。提醒不构成诊断或医疗建议。
- 当前没有账号、云端数据库、云端备份或跨设备同步；测量记录只存于当前设备的小程序本地缓存。
- 后端的请求频率限制和计数保存在进程内存中，服务重启后会重置；多实例部署时各实例之间不共享限制数据。
- 图片会发送到部署者配置的后端，再由后端转发给腾讯云 OCR。服务端不保存原图，但部署环境的访问日志、网络链路和第三方服务仍应纳入隐私管理。
- 当前没有自动遮挡照片中姓名、电话号码、地址或就诊卡等信息的功能；拍摄前请检查画面内容。
